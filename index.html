Metrics picker

PrecisionTP/(TP+FP) - false positives costly
RecallTP/(TP+FN) - false negatives costly (fraud, disease)
F1balance P and R, imbalanced data
Accuracybalanced datasets only
AUC-ROCcompare classifiers, 1 = perfect
MAE/RMSEregression error size
R²variance explained, near 1 = good
ROUGEsummarization (n-gram recall)
BLEUtranslation (precision, brevity penalty)
BERTScoresemantic similarity via embeddings
Perplexitynext-token prediction, lower = better

Confusion matrix = classification · MAE/RMSE/R² = regression · ROUGE/BLEU/BERTScore/perplexity = generated text.

Fit · bias · variance

StateSymptomFix
Overfithigh variance; great on train, bad on newmore data, early stop, augmentation, regularization, ensembles
Underfithigh bias; bad everywherebigger model, more features
Balancedlow bias + low variancethe goal

Split: train 60-80% · validation 10-20% (tuning) · test 10-20% (final).

Hyperparameters (set before training)

Learning ratehigh = fast, may overshoot; low = precise, slow Batch sizesmall = stable, slow; large = fast, unstable Epochstoo few = underfit; too many = overfit Regularizationincrease to cut overfitting

Tune with grid/random search or SageMaker AMT. Model parameters are learned; hyperparameters are not.

Bedrock core

Managed GenAI, one API over many FMs (Titan/Nova, Claude, Llama, Stability). Bedrock copies the FM for you; your data never trains the base model.

Guardrailsblock topics, filter harm, redact PII, cut hallucinations; ContentFilteredCount metric Agentsmulti-step tasks: action groups (OpenAPI + Lambda) + knowledge bases, chain-of-thought LoggingModel Invocation Logs → CloudWatch/S3 NovaAWS FM family: Premier/Pro/Lite/Micro, Canvas (img), Reel (video), Sonic (speech)

Improve the FM: cost ladder

1 Prompt engineering → 2 RAG → 3 Instruction fine-tuning → 4 Domain-adaptation pre-training

Cheapest first; pick the lowest rung that satisfies the scenario. 1-2 never change weights; 3-4 do and need compute.

Supervised FTlabeled prompt/completion pairs in S3 Reinforcement FTreward fn scores outputs: Lambda (objective), judge model (subjective) Distillationteacher → smaller student; cheaper, slight accuracy loss

Fine-tuned models cost more to run: on-demand per token or Provisioned Throughput (required for custom).

Bedrock pricing

On-Demandper token, unpredictable loads Batchup to 50% discount, output to S3 Provisionedreserved capacity/month - NOT a cost saver, required for custom models

Cost drivers: token counts + model size. Temperature / Top K / Top P change NOTHING about price or latency. Latency = model size/type + token counts.

Traps that repeat

  • Cheapest FM improvement wins: prompt < RAG < fine-tune < pre-train.
  • Temperature/Top K/Top P never change price or latency.
  • "Up-to-date info, no training budget" = RAG, not fine-tuning.
  • Kendra searches docs; Personalize recommends products.
  • JumpStart = models in YOUR account; Bedrock = managed API.
  • Deterministic, computable problem = write code, not ML.
  • Low latency offline on device = SLM at the edge.
  • Recall for missed-case cost, precision for false-alarm cost.
  • Provisioned Throughput reserves capacity; Batch saves money.
  • S3: 11 nines durability for ALL classes; availability varies.
